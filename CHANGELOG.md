# Changelog

All notable changes to this project are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

**Every pull request adds its changes under `[Unreleased]` before it is merged.** CI enforces this on every PR, with no skip label, and `main` only accepts squash merges whose checks have all passed (see `scripts/setup_repo_rules.py`). On release, `[Unreleased]` is renamed to the version and date.

Use these headings: `Added`, `Changed`, `Deprecated`, `Removed`, `Fixed`, `Security`. Write one line per change and link the PR.

## [Unreleased]

### Added
- Phase 5.6 live validation on canvas:
  - **Blocked connections.** In the builder, an edit that would make a connection whose typed ports do not fit (a move, a remove, a replace or an add that puts a consumer after a producer whose `output_schema` lacks what its `input_schema` requires) is disabled in its menu, with the reason under it. Edits that keep or remove existing mismatches stay allowed. The browser's check (`@/workflows/ports`) mirrors the engine's `port_mismatch`; `schemas/fixtures/port-checks.json` is run by both so they cannot drift.
  - **Live issues.** Unsaved edits are checked with `POST /workflows/{id}/validate` 400 ms after the last one. Each issue shows on its node's card and at the top of its side panel; the status line counts them and opens a list whose node ids select their card. A failed check says so, with Retry, and blocks nothing.
- Phase 5.5 container nodes drawn with children inside ([#150](https://github.com/KsiProgramming/agentic-dev/pull/150)):
  - **Nested editing.** In the builder every node card has its menu, inside maps, loops, parallels and router routes too: add a step after it (a lone body or branch grows into a new sequence), add a branch to a parallel, move up or down in its own sequence, "Move to…" after any other node or into a new branch, "Replace with…" another kind (so a body or route is never empty), and remove. What would leave a container empty, or a parallel with one branch, is disabled with the reason. Each is one undo step made of the existing graph operations; no engine or API change.
- Phase 5.4 side panel from parameter JSON Schema ([#149](https://github.com/KsiProgramming/agentic-dev/pull/149)):
  - **Side panel.** In the builder, a card's name or "Edit parameters" selects a node, nested ones included, and its parameters are edited in a form drawn from its manifest (`@rjsf/core` with our own theme): text, textareas, choices, the tools an agent may use as checkboxes, port schemas as JSON text in an "Advanced" group. Each accepted change is a `setParam` edit (typing in one field is one undo step); a refused value shows on its field. A pane from 1024 px, a sheet below. With nothing selected, and from "Edit details", it edits the workflow's name, description and budget; the details dialog is gone.
  - **Workflow budget.** The spec takes an optional `budget_usd`; a run's budget is its own, else the workflow's, else the workspace's default (`POST /runs`, rerun and validate). `setParam` without a node sets it.
  - **Manifests.** `parameters` is ready for a form (no nullable `anyOf`, sentence-case titles, tool choices as `enum`s); a new `ui` field gives each primitive's layout. The spec schema is unchanged apart from `budget_usd`.
- Phase 5.3 node manifests and a palette generated from them ([#148](https://github.com/KsiProgramming/agentic-dev/pull/148)):
  - **Manifests.** `agentic_engine.nodes`: one manifest per primitive (label, description, category, icon, parameters as JSON Schema from the node's model, child slots, a default node, fill hints); a test fails when a primitive has none. `GET /node-types` serves them; `schemas/fixtures/node-types.json` holds the same list for the web's tests.
  - **Palette.** The builder's "Add a step after" is a submenu drawn from `GET /node-types`, grouped as Steps, Flow and Combine; it adds any of the nine primitives, containers with their children under fresh ids, and a reduce whose `from` is the step before it. A kind the engine adds appears with no web change; a card of a kind the web does not know is drawn from its manifest, or as a box.

- Phase 4.6 `router` primitive and the "Audit codebase" template ([#142](https://github.com/KsiProgramming/agentic-dev/pull/142)):
  - **Spec.** A `router` node runs one of its routes: the first whose CEL `when` holds (`last`, `results`, `artifacts`), or the one its `classifier` agent picks, else `default`; no match and no default fails it. New issue code `invalid_router` (a route that is not an agent, tool or sequence node). An artifact is written after a router only when every route writes it.
  - **Engine.** The classifier answers through a typed output the engine makes (an enum of the route ids and a reason), so it cannot invent a route. A new `route_chosen` event (`route`, `mode`, `reason`). At the top of a run the choice is checkpointed (`RunState.routes`), so a resumed run goes on in its route without asking again.
  - **Nesting.** Map items and parallel branches now run through one in-process runner, so a branch may hold a router, a nested parallel and a reduce that writes nothing. Agents over `agents_alive` there wait for a slot. A reduce's `from` must be in its own branch, route or body, or around it.
  - **Template.** "Audit codebase" (`audit-codebase`, read-only): the chosen scanners and reviewer agents (security, tests, architecture) run in parallel and are merged by `dedupe` into `findings.json`. A rule router then picks the report (`clean`, `fix_first` or the full one), and its agent writes `report.md`. Options: `checks`, `path`, `min_severity`, `reviewers` (2 or 3 vote on each review), `reviewer_model`, `report_model`.
  - **Findings schema.** Additive in v1: `scanner: "agent"` and the categories `security`, `tests` and `architecture`.
  - **Console.** A router's route nests under it ("Routed to fix_first"), and its Output says which route it took and why, the others marked Skipped. Nested nodes are placed by the run's spec. The run graph is laid out by ELK (`elkjs`, loaded with the tab) and draws routers, with routes not taken Skipped.
  - **New run form.** Template options may be whole numbers and lists of choices (checkboxes).
  - **Settled join.** A `parallel` may take `join: "settled"`: it waits for every branch and completes if one did, cancelling none. The audit's checks use it, so a failed check no longer fails the audit; the merged report lists it as a failed check with the reason.
  - **Typed outputs.** An agent's answer that ends with its JSON object after a sentence is now parsed (a real audit's test review was refused for it).
  - **Roadmap.** New phase 4.8, .NET analyzers in the sandbox, after a test audit of a .NET repo was not linted at all.
  - **Roadmap and board, done by hand.** GitHub Actions cannot run on this repo (no credits left), so CI could not run. Phase 4.6 was marked done in `specs/roadmap.md` with `scripts/check_roadmap.py --mark-done`, and the board synced with `scripts/sync_roadmap_board.py`; #69 (the retired 4.7) was closed as merged into #68.
  - Sample specs: `router-rule`, `router-classifier`, `router-in-map` and `parallel-nested-vote`.
- Phase 4.5 `reduce` strategies, dedupe and vote ([#141](https://github.com/KsiProgramming/agentic-dev/pull/141)):
  - **Spec.** `reduce` takes `strategy: "dedupe"` or `"vote"` (with optional `min_votes`, default a majority of the sources that completed), and `from` may name a `parallel` as well as a map, for every strategy.
  - **Engine.** Both strategies merge findings reports with no model call. Findings with the same `fingerprint` are one issue; an agent's finding without one is matched by category, path, line and rule. A merged finding keeps the highest severity and lists the `sources` that reported it. Its `confidence` is the share of sources that reported it, times their own confidence. `vote` keeps the issues `min_votes` sources reported, and fails when fewer sources completed. A source that is not a findings report fails the reduce, with the typed-port error format. `node_completed` carries `merged: {sources, findings_in, findings_out}`.
  - **Findings schema.** Additive in v1: `scanner: "merged"`, an optional `fingerprint` on input, and per finding `confidence` and `sources`; the report gains `sources`. The model moves to `agentic_runtime.findings`, re-exported by `agentic_tools.scan.report`.
  - **Validation.** New issue code `invalid_vote` (a `min_votes` the parallel's join can never reach). A merging reduce's output is typed as a findings report, so `port_mismatch` checks the next node and a source whose `output_schema` has no `findings` array.
  - **Console.** The Findings view of a merged report says which sources it came from, adds a Confidence column and "Found by 2 of 3" under each finding. A merging reduce's step line reads "Merged 42 findings into 30 from 3 sources". A new `Percent` display component.
  - **Console output.** A merging reduce logs no output of its own, so its Output loads the findings artifact it wrote. The run graph labels reduces Dedupe and Vote.
  - Sample specs: `findings-merge` (two scans and a reviewer in parallel, merged into `findings.json`, then summarised) and `findings-merge-scans` (four overlapping scans, then `dedupe` and `vote`, no model).
  - **Roadmap and board, done by hand.** GitHub Actions cannot run on this repo (no credits left), so CI could not run. Phase 4.5 was marked done in `specs/roadmap.md` with `scripts/check_roadmap.py --mark-done`, the command the "Roadmap phase marked done" job runs. The project board was synced with `scripts/sync_roadmap_board.py`, what `roadmap-board.yml` runs. The checks were run locally, as listed in the PR.
- Phase 4.4 deterministic tool nodes, linter, dependency scanner and secret scanner ([#140](https://github.com/KsiProgramming/agentic-dev/pull/140)):
  - **Tools.** A read-only `scan` MCP server for every run with a sandbox: `scan.lint`, `scan.secrets` and `scan.dependencies`. Each returns one findings report (`schemas/findings.v1.json`): what was checked where and why anything was skipped, then the findings most severe first, each with a stable `fingerprint`. The workflow's author picks the checks; they need a repo, like `repo.*`.
  - **Lint follows the repo's own stack.** With `linters: "auto"`, each module gets the linter its own config names (ruff, Biome, ShellCheck). A module configured for a linter the sandbox cannot run (ESLint, flake8, pylint) is skipped with the reason, never linted by another tool. A module with no linter config gets conservative platform rules, its findings marked `platform-default`. Module detection is shared with `repo.list_modules`.
  - **Secrets and dependencies.** gitleaks runs redacted, and a finding never carries the secret. osv-scanner runs offline against the OSV database in the image (8 ecosystems), and the report gives its date.
  - **Sandbox image.** Pinned, checksummed scanner releases for amd64 and arm64 and the OSV database. The image grows from about 20 MB to about 510 MB.
  - **Console.** A scan step's Output and a findings artifact show counts by severity, what was checked, and the findings as a table (cards on small screens). Severity is shown as an icon and a word, never a status colour. The scan tools have their own lines in the activity.
  - A `scan-specialists` sample spec: three scans in parallel write `lint.json`, `secrets.json` and `dependencies.json`, and a security specialist reads all three.

- Phase 4.3 shared run context, named artifacts in the run workspace ([#139](https://github.com/KsiProgramming/agentic-dev/pull/139)):
  - **Spec.** `agent`, `tool` and `reduce` nodes take `writes: "findings.json"`; `agent` and `tool` nodes take `reads: [...]`. Names end in `.json`, `.md` or `.txt`.
  - **Engine.** A writer's output is stored as a new version once it completes (`artifact_written`); a `.json` artifact must be JSON, and sizes are capped at 1 MB each and 8 MB per run. A reader's input is the versions the run had when it started (its `node_started` names them), and a name not written yet fails it before it runs. Loop conditions and map `over` read `artifacts` in CEL. The state keeps refs only, so checkpoints stay small.
  - **Validation.** New issue codes `artifact_unknown` (a read with no earlier writer) and `artifact_conflict` (a write inside a map, or two parallel branches writing one name). `port_mismatch` follows a read to its writer.

  - **Tools and sandbox.** A read-only `artifacts` MCP server (`artifacts.list`, `artifacts.read`) for every run. A run with a sandbox gets a read-only copy of each artifact in `/workspace/artifacts`, copied again into a fresh sandbox.
  - **Console and Inbox.** A step lists the artifacts it wrote (Output) and read (Input) as cards that open their content (JSON view, sanitised Markdown or text) with Download. An Artifacts view sits beside Steps and Graph (`?view=artifacts`). A gate's review lists the run's artifacts in the Inbox and the dock.

- Phase 4.2 typed ports ([#138](https://github.com/KsiProgramming/agentic-dev/pull/138)):
  - **Spec.** `agent` and `tool` nodes take optional `input_schema` and `output_schema`: JSON Schema 2020-12 with an object root, only local `$ref`s, at most 16 KB.
  - **Engine.** A node's input is checked before it starts and its output once it completes. A value of the wrong shape fails the node with one line naming the node, the side and the JSON pointer, and `node_failed` carries a structured `port`. An agent with an `output_schema` is asked for JSON and its answer is parsed (one fenced block allowed). A typed output becomes the node's `data` and reaches the next node as JSON.

  - **Console.** A step failed by a port shows a "Wrong shape" alert with each pointer and message, and its Input tab shows the node's schemas.

- Phase 11.3 approval expiry ([#131](https://github.com/KsiProgramming/agentic-dev/pull/131)):
  - **Time to live.** A gate waits at most `approval_ttl_s`, a new run limit (72 h, the platform's default and ceiling; a workspace may lower it in the "Run limits" card, in hours), frozen on the run with its other limits. A gate may set a shorter `ttl_s` of its own; a longer one is a `policy_limit` issue. `gate_waiting` carries `ttl_s` and `expires_at`, and `GET /runs` shows it on `waiting_gate.expires_at`.
  - **Expiry.** Every worker sweeps every `GATE_SWEEP_S` (30 s): a run waiting past its gate's expiry, with no decision, is cancelled like a user's cancel. It ends `run_cancelled` `{reason: "Approval expired", expired: true}` and its kept sandbox is removed; nothing is approved or rejected. A decision sent after the expiry is refused with `409`. The audit log records `gate.expired`, and `run.ended` carries the `cancel_reason`.
  - **Old gates.** Alembic `0021_approval_expiry` adds `runs.gate_expires_at`, `runs.cancel_reason` and `workspace_policies.approval_ttl_s`, and gives every gate already waiting 72 h from when it paused, so stale ones expire on the first sweep after the deploy.
  - **API.** Run summaries add `cancel_reason` and `expired`; the policy endpoints add `approval_ttl_s`. The JSON Schema, OpenAPI spec and web client are regenerated.
  - **UI.** An expired run shows "Expired" in Cancelled's grey in the runs list and the console, with the reason; it no longer counts as waiting in the sidebar, the page title or "Needs approval", even in the seconds before the sweep. The approval dock says when the gate expires ("Expires in 2 d") through a new `ExpiresIn` display component.

- Phase 1.9 `loop` primitive and CEL expressions:
  - **CEL conditions** (`agentic_engine.expr`, using `cel-python`). `compile_condition` parses a condition once and rejects syntax errors, unknown variables and unknown functions, with the column. `CompiledCondition.evaluate` returns a bool or raises `ExpressionError` with a short message. No custom functions are registered.

  - **Tests.** The a11y spec scopes a settings alert to the page content (Next's route announcer is an alert too), and the keyboard gate test allows the "(N) ● Needs approval" prefix that other waiting runs add. The specs read a run's status and approval dock only where visible: Next keeps a previous run's console, and React a streamed copy of the page, hidden in the DOM. The sheet's layout check waits for its slide-in to finish.
- A run's `usage` now adds up every node run (the new `RunState.usage`, with `Usage` allowed in checkpoints). Before, it counted only each node's latest result, which undercounted loops. `run_resumed`'s `completed_nodes` lists each node once.
