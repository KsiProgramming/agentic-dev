# Changelog

All notable changes to this project are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

**Every pull request adds its changes under `[Unreleased]` before it is merged.** CI enforces this on every PR, with no skip label, and `main` only accepts squash merges whose checks have all passed (see `scripts/setup_repo_rules.py`). On release, `[Unreleased]` is renamed to the version and date.

Use these headings: `Added`, `Changed`, `Deprecated`, `Removed`, `Fixed`, `Security`. Write one line per change and link the PR.

- Phase 1.10 `map` and `reduce` primitives ([#19](https://github.com/KsiProgramming/agentic-dev/pull/19)):
  - **`map` node.** A spec node (`{"type": "map", "id", "over", "body", "max_concurrency"}`) runs its body once per item of the CEL list `over`, at most `max_concurrency` (1 to 8) at a time and at most 40 items. Its result keeps item order (`data`: `items`, `outputs`). The body can hold only agent, tool and sequence nodes, and a map cannot be inside a loop (`map_errors`, `loop_errors`).
  - **`reduce` node.** A spec node (`{"type": "reduce", "id", "from", "strategy"}`) combines the outputs of an earlier map: `concat` (optional `separator`) or `agent` (`agent`: role, instructions, provider, model), whose input is the JSON array `[{item, output}]`.
  - **CEL lists.** `compile_list` and `CompiledList.evaluate` (`agentic_engine.expr`) evaluate an expression over `last` and `results` to a JSON list.
  - **Engine.** A map compiles to an entry node, an `<id>.item` worker started once per item with LangGraph `Send`, and an `<id>.join` node. `RunState` gains `map_results`, checkpointed per item. The new `map_item_started` and `map_item_completed` events wrap each item, and the events of nodes inside a map carry `item`. The spec limits `MAX_AGENTS_ALIVE` (8) and `MAX_AGENTS_SPAWNED` (40) are named constants.
  - **Demo.** New spec fixtures `map-modules.json` and `map-reduce-agent.json`, and a README section on map and reduce. The exported schema and the API client include both nodes.
- Phase 1.9 `loop` primitive and CEL expressions:
  - **CEL conditions** (`agentic_engine.expr`, using `cel-python`). `compile_condition` parses a condition once and rejects syntax errors, unknown variables and unknown functions, with the column. `CompiledCondition.evaluate` returns a bool or raises `ExpressionError` with a short message. No custom functions are registered.
  - **`loop` node.** A spec node (`{"type": "loop", "id", "body", "until", "max_iterations"}`, at most 5 iterations) runs its body until `until` is true or `max_iterations` is reached. Both stops complete the loop, with `stop_reason` and `iterations` in its result. The spec rejects an invalid `until`, and a gate, writer, publisher or loop inside a loop body (`loop_errors`). The exported schema and the API client include it.
  - **Engine.** The compiler now builds the graph recursively, and a loop adds an entry node, its body and an `<id>.check` node. The new `loop_iteration_started` and `loop_condition_evaluated` events mark each iteration. `RunState` gains `iterations`, which is checkpointed, so a resumed run continues the same iteration. The LangGraph recursion limit is computed from the spec (`recursion_limit`).
  - **Demo.** New spec fixture `review-loop.json` and a README section on loops.
- Phase 1.8 `github.openPR` behind a gate:
  - **`github` MCP server** (`agentic_tools.github`). Its one tool, `github.openPR(from_node, title, body?, base?)`, bundles a writer's branch out of the sandbox, pushes it from the worker with an installation token, and opens a pull request. It returns the PR as structured content. The push only creates the branch or finds it already at the same commit, and an open PR from the branch is reused.
  - **Tools.** `RunTools` routes a run's calls to the `repo` and `github` executors. `ToolOutput` gains `data`, filled from MCP structured content. The new `strict_tool` builds the strict, example-carrying tools both servers use.
  - **`agentic_github`.** `GithubApp` gains `installation_token` and `open_pull_request`. The package also adds `push_bundle`, `repo_full_name`, `github_remote` and `auth_env` (the token as an HTTP header through `GIT_CONFIG_*`), the errors `PushError` and `PullRequestError`, and the model `PullRequestInfo`.
  - **Sandbox.** `Sandbox` gains `staging_dir` and `take_file`, and `export_branch` bundles `<clone HEAD>..<branch>`. `clone_shallow` and `SandboxManager.open` take a `git_env`, which is applied only to https clones.
  - **Engine.** The spec now refuses a publishing tool (`PUBLISH_TOOLS`) unless it is called by a tool node whose `from_node` is an earlier writer, with a gate between the two (`publish_gate_errors`). A completed publishing node writes the new `pr_opened` event. `AgentNodeResult` gains `data`. `WRITE_TOOLS` is now defined in the spec.
  - **API.** `POST /runs` refuses `github.*` tools without a GitHub `repo` (`422`) and without a GitHub connection in the workspace (`409`).
  - **Worker.** It reads the API's `GITHUB_APP_*` settings (compose passes them and mounts the key). It clones GitHub repos with an installation token, so private repos work. It opens the `github` tools for runs that use them. Empty environment variables now count as unset.
  - **Demo.** New spec fixture `open-pr.json` and a README section on pull requests.
- Phase 1.7 `gate` primitive and approvals ([#16](https://github.com/KsiProgramming/agentic-dev/pull/16)):
  - **`gate` node.** A spec node (`{"type": "gate", "id", "title", "prompt"?}`) pauses the run with a LangGraph `interrupt()` until a human decides (`agentic_engine.gate`, `GateDecision`). The run writes `node_started` and the new `gate_waiting` event (`title`, `prompt`, `artifact`), and `run_workflow` returns status `waiting` with `waiting_at`. `resume_workflow` takes `decision=`: the gate writes `gate_decided`, then approve continues and reject ends the run `cancelled` at the gate. A spec with a gate needs a checkpointer. The exported schema and the API client include it.
  - **Approvals.** Alembic `0009_approvals` adds the `approvals` table. `agentic_store` gains `record_approval`, `pending_decision`, `waiting_run_ids` and their errors. Runs get the `waiting` status; `run_resumed` now sets a run back to `running`. A decision resets the run's `attempt` count.
  - **API.** New `POST /runs/{id}/approvals` (`202`, `404`, `409`, `422`), which queues the run again.
  - **Worker and sandbox.** A run paused at a gate is released and keeps its sandbox: `SandboxManager` gains `keep(run_id)` and `open(..., reuse=True)`, and the startup sweep spares waiting runs. The worker continues an approved run in its kept sandbox, so a writer's commits survive the gate.
  - **Demo.** New spec fixture `gate-approval.json` and a README section on gates.
- Phase 1.6 `tool` primitive, `repo` write tools and a worktree per writer:
  - **`tool` node.** A spec node (`{"type": "tool", "id", "tool", "args"}`) calls one platform tool with fixed arguments and no model, writing a `tool_call` and a `tool_result` event. Its output becomes the next node's input, and an error result fails the node (`agentic_engine.tool.run_tool_node`). `run_workflow` and `resume_workflow` take `tools=`. The exported schema and the API client include it.
  - **Write tools.** The `repo` MCP server gains `repo.write_file` (1 MiB, confined to the worktree, `.git` and symlinks refused) and `repo.commit` (commits as `agentic-dev agent`, with hooks, fsmonitor and signing off).
  - **Writers.** A node whose spec names a write tool is a writer (`agentic_engine.spec.writer_node_ids`). On its first call it gets its own worktree on `agent/<run>/<node>` (`agentic_sandbox.add_worktree`, `Worktree`), and `open_repo_tools(sandbox, run_id=, writers=)` routes its calls there through the new `RepoTools`. `ToolExecutor.call` takes `node_id`, which `ClaudeRuntime` and `FakeRuntime` pass. Nothing is pushed.
  - **Sandbox.** A new sandbox image, `agentic-dev/sandbox:dev` (alpine + git, `packages/sandbox/Dockerfile`), is built by compose and CI and is the new `SANDBOX_IMAGE` default. `Sandbox` gains `worktrees_dir`, `exec(cwd=)` and `put_file`. The shared checkout stays root-owned and read only.
  - **Demo.** New spec fixtures `tool-node.json` and `write-file.json`, and CI runs the phase 1.6 write demo in the compose job.
- Phase 1.5 GitHub App install and repos. A new `agentic_github` package (on `githubkit`) wraps the platform's GitHub App: `GithubAppConfig.from_file`, and `GithubApp` with `get_installation` (App JWT), `list_repos` (installation token, cached, paginated) and errors that never carry a token (`InstallationNotFoundError`, `GithubApiError`). `agentic_github.testing` has GitHub payloads and a test key. Alembic `0008_github_connections` lets a connection hold no secret: a `github` connection stores the installation id (`external_id`) and `account_login`, enforced by a check constraint. `agentic_store` gains `put_github_connection` and `get_github_installation`; a lost master key no longer drops it. New API routes: `POST /workspaces/{id}/connections/github/install` (install URL with a single-use `state` in Redis), `GET /github/setup` (the App's Setup URL), `GET /workspaces/{id}/repos` and `DELETE /workspaces/{id}/connections/github`; `GET /workspaces/{id}/connections` now lists every provider, with `account_login`. New API settings `GITHUB_APP_ID`, `GITHUB_APP_SLUG`, `GITHUB_APP_PRIVATE_KEY_FILE` and `WEB_BASE_URL`; empty variables now count as unset. - Phase 1.4 workspaces, connections and encrypted secrets. A new `agentic_secrets` package provides:
  - a `KeyProvider` protocol, and `LocalKeyProvider`, which reads a 32-byte master key from `MASTER_KEY_FILE`;
  - envelope encryption: AES-256-GCM, one data key per workspace, ciphertexts bound to their row;
  - `python -m agentic_secrets generate-key`;
  - a log `RedactingFilter` and `redact_json` for live secrets.

  Alembic `0007_workspaces_connections` adds `workspaces` (with a `Default` workspace), `connections` and `runs.workspace_id`. `agentic_store` gains `put_connection`, `load_secret`, `list_connections`, `delete_connection`, `list_workspaces` and `get_workspace`. New API routes: `GET /workspaces`, `GET /workspaces/{id}/connections`, and `PUT`/`DELETE /workspaces/{id}/connections/claude`; the key is write only and shown by its last 4 characters. `POST /runs` takes an optional `workspace_id`. On Claude, the worker builds each run's own client from its workspace's stored key, closes it when the run ends, and redacts the key from logs and event payloads. A new Settings page (`/settings`) stores, replaces and removes the key. Compose gains a `keygen` one-shot and a `secrets` volume. `MockClaude.make_client` records the key each call sends.
- Phase 1.3 durable execution: runs are checkpointed in Postgres after each node with the LangGraph Postgres checkpointer (`langgraph-checkpoint-postgres`, psycopg), and a run whose worker dies is resumed by another worker after its last completed node (AC-8). `run_workflow(..., checkpointer=)` and the new `resume_workflow` in `agentic_engine.graph`; `checkpoint_serde()` allows only the engine's state types to be loaded from a checkpoint. A resumed attempt writes the new `run_resumed` event (`attempt`, `completed_nodes`) and continues `seq` (`RunEventLog(next_seq=)`, `agentic_store.max_event_seq`). Workers lease runs (`agentic_store.lease`: `claim_run`, `renew_lease`, `reclaim_expired_run` with `SKIP LOCKED`, `release_run`) and reclaim those whose lease expired; a run claimed more than `MAX_ATTEMPTS` times fails. Alembic revisions `0005_run_lease` (`runs.worker_id`, `lease_expires_at`, `attempt`) and `0006_checkpoints` (the saver's tables). New worker settings `WORKER_ID`, `LEASE_TTL_S`, `LEASE_HEARTBEAT_S`, `MAX_ATTEMPTS`. New spec fixture `three-step-sequence.json` and a kill/restart demo in the README.
- Phase 1.2 `repo` MCP server (read only): the new `agentic_tools` package serves `repo.list_files`, `repo.read_file` (numbered lines, line ranges, 2,000-line / 256 KiB cap, binary files refused) and `repo.search` (fixed string or extended regex, optional case-insensitivity, up to 500 `path:line: text` hits) from an MCP server built per run with the official MCP Python SDK (`mcp`). The tools run inside the run's sandbox and stay confined to the repo, symlinks included. `McpToolExecutor` bridges an MCP client to the existing `ToolExecutor`, and `open_repo_tools(sandbox)` connects a run's agents to the server in memory. The worker gives every run with a repo these tools and closes the MCP client before the sandbox. `FakeRuntime` calls the tools of an unscripted node with the first `examples` entry of each tool's input schema. New spec fixture `ask-repo.json`; `scripts/sandbox_demo.py` takes `--spec` and repeatable `--expect`, and CI runs the phase 1.2 demo in the compose job.
- Phase 1.1 sandbox manager: new `agentic_sandbox` package. `RepoSource` accepts an `https://` URL without credentials or a local path under `SANDBOX_LOCAL_ROOT`, with an optional ref. `clone_shallow` makes a depth-1 clone on the worker with only the https and file protocols enabled. There are two `SandboxManager` backends:
  - `DockerSandboxManager`: one container and volume per run, labelled `agentic.run_id`. The container has no network, a read-only root, no capabilities, a non-root user and resource limits. Both are removed when the run ends, and `sweep_orphans` removes leftovers at worker startup.
  - `FakeSandboxManager`: a temp directory on the worker, with no isolation.

  `SandboxTools` provides the first repo tool, `repo.list_files`, which runs inside the sandbox and refuses paths that leave the repo. `POST /runs` takes an optional `repo` (Alembic `0004_run_repo`) and returns `422` when a node uses `repo.*` tools without one. The worker opens a sandbox per run with a repo and gives its runtime the sandbox's tools. A sandbox that cannot be created ends the run with `run_failed` (`record_unstarted_run`). New settings: `SANDBOX_BACKEND`, `SANDBOX_IMAGE`, `SANDBOX_LOCAL_ROOT`, `DOCKER_GID`. `FakeRuntime(tools=...)` runs `CallTool` script steps, and with tools set it calls each tool a node names. Compose mounts the Docker socket and this repo's git history as a demo repo, and `scripts/sandbox_demo.py` runs the demo in the CI smoke job.
- Phase 0.8 minimal monitor page: the home page starts a sample run, and `/runs/[id]` lists the run's events live from the SSE stream (`useRunEvents` hook on `EventSource`, ordered and de-duplicated by `seq`, status from the final event, a "not found" state for unknown runs, payloads shown as text only). The API allows browser origins from `CORS_ORIGINS` and documents `RunEvent` in its OpenAPI spec, so the web client gets a generated type for it. - Phase 0.7 Claude adapter: `agentic_runtime.claude.ClaudeRuntime` runs agent nodes on the Anthropic Messages API (`anthropic` SDK). It streams `text_delta` events, emits one `usage` event per API call, maps API errors to `failed` with a `retryable` flag, supports cooperative cancel, and has a tool-use loop over an injected `ToolExecutor` (`agentic_runtime.tools`, capped by `max_turns`). The worker picks the runtime with `AGENTIC_RUNTIME=fake|claude` and reads `ANTHROPIC_API_KEY` (as a secret), `CLAUDE_MODEL`, `CLAUDE_MAX_TOKENS` and `CLAUDE_MAX_TURNS`; it fails fast without a key. Test helpers in `agentic_runtime.testing`: `MockClaude` (real SDK on an in-memory transport), `ScriptedToolExecutor` and `collect_and_check`.

### Changed
- The `CHANGELOG.md updated` check runs on every PR and needs lines added to the file; the `skip-changelog` label no longer skips it ([#29](https://github.com/KsiProgramming/agentic-dev/pull/29)).
- Phase 2.5 ([#27](https://github.com/KsiProgramming/agentic-dev/pull/27)):
  - The engine writes at most one `text_delta` per node (and map item) every 250 ms (`agentic_engine.graph.deltas.DeltaBuffer`). The first chunk of a burst is written at once and the rest are joined. Any other event of the node, its end and cancellation write the pending text first, so order and the joined text are unchanged.
  - `run_cancelled` takes its `reason` from the cancel message (`task.cancel("…")`); a bare cancel still says `caller cancelled`.
  - `SandboxManager` gains `discard(run_id)`, which removes a sandbox a run kept at a gate.
  - The run page no longer lists one table row per event (`RunEvents` removed); the event table moved to the Raw events tab.
- Phase 2.2 routes: today's home page (Generate docs card and sample run) moved to `/templates`. `/` redirects to `/runs`, which shows an empty state until run history arrives in 2.4. Page titles read `<Page> · Agentic Dev`.
- Phase 2.1: home, run monitor and settings use only shared components and tokens. The run status is a `StatusBadge` (`data-status` holds the status), the event list uses the Table primitive, the gate panel is an amber card with a toast on decision, and failed loads (repos, GitHub, a lost event stream) can be retried.
- Docker sandboxes run from `agentic-dev/sandbox:dev` instead of `alpine:3.20`. A missing local image is reported with the command that builds it.
- A Docker sandbox is now removed even when its run is cancelled during teardown. Before, a stopping worker could skip the removal and leave the container until the next startup sweep.
- The worker no longer shares one Anthropic client between runs: each run on Claude gets its own client, built from its workspace's stored key. `RunRuntimes` opens a runtime per run, and `AttemptSink` redacts live secrets from event payloads.
- Stopping the worker no longer cancels the run in flight: it releases the run unfinished (no `run_cancelled`) and the next worker resumes it. On Windows, `python -m agentic_worker` runs on a selector event loop, which psycopg needs.
- The worker's startup sweep keeps the sandboxes of runs other workers hold a lease on, and `DockerSandboxManager.open` replaces a sandbox an earlier attempt of the same run left behind.
- The `two-step-sequence.json` spec fixture no longer lists `repo.*` tools, since a run that uses them now needs a `repo`. `list-repo-files.json` is the fixture for repo tools.
- The worker image installs `git`, and the worker builds its runtime per run (sharing one Claude client) so each run's agents get its own sandbox tools.
- Worker and API tests no longer read the developer's `.env`, so they never run on Claude with a real key by accident.
- The worker moved from `agentic_engine.worker` to the `agentic_worker` package (`python -m agentic_worker`); `agentic_engine` no longer depends on Redis or pydantic-settings.
- `PostgresEventSink` no longer creates the `runs` row: create it with `create_run` first, and `run_started` moves it from `queued` to `running`.

### Removed
- `ANTHROPIC_API_KEY`: the worker no longer reads a Claude key from the environment (settings, compose and `.env.example`). Store it on the Settings page or with `PUT /workspaces/{id}/connections/claude`.
- `agentic_sandbox.SandboxTools` and `LIST_FILES`: the repo tools moved to the `repo` MCP server in `agentic_tools`, and `agentic_sandbox` no longer depends on `agentic_runtime`.

### Fixed
- `github.openPR` no longer fails with "git fetch failed: transport 'file' not allowed" after an approved gate. git checks the file transport when fetching the writer's bundle, and `push_bundle` only allowed it for `file://` test remotes. It is now allowed for the bundle fetch only, and fetch and push to GitHub stay https only.
- The "Generate docs" writer no longer fails with "Claude stopped without finishing: max_tokens": the Claude runtime's defaults are now 32,000 output tokens per call (was 4,096) and 50 tool-use turns (was 10), and compose passes `CLAUDE_MAX_TOKENS` and `CLAUDE_MAX_TURNS` to the worker.
- A run's `usage` now adds up every node run (the new `RunState.usage`, with `Usage` allowed in checkpoints). Before, it counted only each node's latest result, which undercounted loops. `run_resumed`'s `completed_nodes` lists each node once.
